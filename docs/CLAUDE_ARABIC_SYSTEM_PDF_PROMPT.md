# Prompt لـ Claude: دليل عربي PDF لنظام رشيد المالي (مع لقطات شاشة)

الصق هذا الملف كاملاً في Claude (أو Claude Projects / Artifacts) واطلب منه إنتاج **ملف PDF عربي** حسب التعليمات أدناه.

---

## دورك

أنت كاتب توثيق منتج عربي لنظام **رشيد المالي (Rashid Financial)** — نظام إدارة مالية قائم على المشاريع (صحائف يومية، صناديق، تقارير، مخزون).

المطلوب النهائي:

1. مستند **PDF عربي** جاهز للطباعة أو المشاركة مع الإدارة/المحاسبة.
2. لغة واضحة للمستخدم غير التقني (محاسب / مدير صندوق)، مع الحفاظ على دقة المصطلحات.
3. لكل شاشة رئيسية: **شرح مختصر + شرح كل خانة/عمود/زر + مكان لقطة شاشة**.
4. لا تخترع ميزات أو حقول غير موجودة في المواصفات أدناه.
5. استخدم الأرقام والأمثلة الواردة هنا كما هي.

إذا لم تتوفر لقطات شاشة حقيقية، ضع **صناديق placeholder** بهذا الشكل تحت كل قسم:

```
┌──────────────────────────────────────────────┐
│  [لقطة شاشة: اسم الشاشة — وصف ما يظهر]       │
│  المسار المتوقع في الواجهة: ...              │
└──────────────────────────────────────────────┘
```

وإذا أُرفقت صور لاحقاً، استبدل الـ placeholders بها مع تسمية الشكل: «شكل 1»، «شكل 2»…

---

## هيكل الـ PDF الإلزامي (بالترتيب)

1. الغلاف + فهرس المحتويات
2. مقدمة النظام والأدوار
3. **سد العجز اليومي من إجمالي النسبة الإدارية للصناديق** (فصل مستقل مفصل)
4. شرح كل تاب / شاشة في النظام
5. التقارير المتقدمة — مع تركيز خاص على **تقرير المخزون**
6. شرح كل خانات **الصندوق الإداري**
7. **قاموس شامل لكل خانات النظام** (ملحق مرجعي)
8. خاتمة + مصطلحات سريعة

اتجاه الصفحة: يمين لليسار (RTL). عناوين واضحة، جداول للمقارنة، أمثلة رقمية قصيرة.

---

## مصادر الحقيقة (لا تخالفها)

- منطق الصحيفة اليومية: Stage 3 = سد عجز نفس اليوم من فائض النسبة الإدارية لمشاريع أخرى في **نفس التاريخ فقط**.
- Case 1 = تغطية عجز المشروع من **نسبته الإدارية لنفس اليوم**.
- صندوق إداري: بعض البنود **صادر** وليست وارد (انظر القسم 6).
- الملخص الشهري `project_net_result` = **صافي الصندوق** (آخر `fund_balance` حتى نهاية الشهر)، وليس إجمالي الشهر التشغيلي في محطة النقد.
- المساهمة الشهرية تخصم من صافي صندوق المساهم وتزيد/تخفض المستفيد حسب النوع.

# 2) فصل إلزامي: سد العجز اليومي من إجمالي النسبة الإدارية للصناديق

## العنوان العربي المقترح للفصل

**سد العجز اليومي من إجمالي النسبة الإدارية للصناديق (التلقائي — نفس اليوم)**

## الفكرة بجملة واحدة

إذا بقي مشروع بعجز في **صافي الصندوق** بعد أن غطّى ما يستطيع من نسبته الإدارية لنفس اليوم، يسحب النظام تلقائياً من **النسبة الإدارية المتبقية** لمشاريع أخرى في **نفس يوم الصحيفة** لسد جزء/كل العجز — دون طلب موافقة ودون استخدام رصيد النسبة الإدارية التاريخي للمنظمة.

## ما الذي ليس هذا؟

| آلية | هل هي Stage 3؟ |
|------|----------------|
| Case 1: تغطية عجز المشروع من نسبته هو | لا — تسبق Stage 3 |
| رصيد النسبة الإدارية التاريخي للمنظمة (مساهمة يدوية في الصحيفة) | لا |
| مساهمة الملخص الشهري | لا |
| تسوية الدين الإداري من فائض الشهر | لا |
| سداد دين قديم عبر زر سداد الدين | لا — Stage 3 لا تسدد ديوناً قديمة |

## الترتيب داخل الحساب اليومي (مبسط للمستخدم)

1. حساب الوارد / الصادر / النسبة الإدارية / الخصم التشغيلي / إجمالي اليوم.
2. تحديث **صافي الصندوق**.
3. **Case 1**: إن وُجد عجز، يُستخدم من نسبة المشروع لنفس اليوم لتغطيته جزئياً أو كلياً، ويُسجَّل دين إداري لذلك اليوم.
4. **Stage 3** (هذا الفصل): إن بقي عجز بعد Case 1، يُوزَّع تلقائياً من نسب متبقية لمشاريع أخرى في نفس اليوم.
5. تراكم الدين الإداري المتراكم لليوم.

## قواعد التوزيع (اكتبها بوضوح في الـ PDF)

- المصدر = مشروع لديه نسبة إدارية متبقية بعد Case 1، وصافي صندوقه غير سالب قبل التحويل.
- المستفيد = مشروع ما زال صافي صندوقه سالباً بعد Case 1.
- مشروع واحد **لا يكون** مصدراً ومستفيداً في نفس اليوم.
- **أولوية التوزيع:** عجز اليوم أولاً (`daily_total < 0`)، ثم العجز المرحّل فقط (`daily_total >= 0` مع صافي سالب). داخل كل مجموعة: ترتيب `project_id` تصاعدياً. المصادر أيضاً بـ `project_id` تصاعدياً.
- التحويل **متوازن صفرياً** على مستوى المنظمة: ما يزيد عند المستفيد ينقص عند المصدر في صافي الصندوق.
- أي عجز يتبقى بعد نفاد المصادر يبقى سالباً (لا يُختلق مال).
- النسبة المتبقية بعد الإعطاء **لا تُرحَّل لليوم التالي**.

## الحقول الظاهرة في الصحيفة (اشرحها مع مثال)

| الحقل (API) | الاسم العربي المقترح | المعنى |
|-------------|----------------------|--------|
| `administrative_pool_relief` | كم أخذ من النسبة الإدارية | ما استلمه المستفيد من مشاريع أخرى (نفس اليوم) |
| `administrative_pool_relief_given` | كم أعطى من النسبة الإدارية | ما أعطاه المصدر لسد عجز الآخرين |
| `administrative_fee_remaining` | النسبة الإدارية المتبقية | المتبقي من نسبة اليوم بعد Case 1 وبعد الإعطاء |
| `fund_balance` | صافي الصندوق | يتغير: ↑ للمستفيد، ↓ للمصدر |
| `administrative_debt` | الدين الإداري لليوم | يزيد عند المستفيد بمقدار ما أُخذ من البركة (مثل Case 1) |
| `daily_total` | إجمالي اليوم | **لا يُعاد حسابه** بسبب Stage 3 |

## مثال رقمي للـ PDF

- مشروع عاجز: إجمالي يوم سالب → بعد Case 1 ما زال العجز 200.
- مشروع فائض نفس اليوم: نسبة إدارية متبقية 600.
- Stage 3 ينقل 200:
  - المستفيد: صافي الصندوق ↑ 200، دين اليوم ↑ 200، `administrative_pool_relief` = 200.
  - المصدر: صافي الصندوق ↓ 200، `administrative_pool_relief_given` = 200، `administrative_fee_remaining` تنخفض بمقدار 200.
- مجموع أصافي الصناديق لكل المشاريع لا يتغير بسبب Stage 3 وحدها.

## لقطة شاشة مطلوبة هنا

- جدول الصحيفة اليومية يظهر عمودَي «أخذ / أعطى» + صافي الصندوق قبل/بعد إن أمكن.
- صف مستفيد وصف مصدر في نفس التاريخ.

# 3) شرح كل تاب / شاشة

لكل شاشة أدناه أنشئ قسماً في الـ PDF بهذا القالب:

```
### اسم الشاشة
- الغرض (جملتان)
- من يدخلها (الأدوار)
- أهم الإجراءات (حفظ / تصفية / شهر وسنة…)
- جدول: اسم الخانة الظاهر → المعنى بالعربية → هل يدوي أم محسوب
- ملاحظات مهمة / أخطاء شائعة
- [لقطة شاشة]
```

## 3.1 لوحة التحكم (Dashboard)

- ملخص يوم: وارد / صادر / خصم تشغيلي.
- نسبة إدارية حالية.
- أصناف منخفضة المخزون.
- نافذة حركة نقد 7 أيام + إجمالي الشهر حتى اليوم.
- عند وجود نشاط شهري: قائمة مشاريع محطة النقد وحالة فائض/عجز/دين.

## 3.2 المشاريع والتصنيفات

- التصنيف = نوع المشروع (عربي فقط).
- حالة المشروع، إعفاء إداري، نسبة إدارية، نوع الخصم التشغيلي (نسبي / ثابت / معفى).
- لا تحذف مشروعاً له قيود في الصحيفة دون فهم القيود.

## 3.3 الصحيفة اليومية

اشرح كل الأعمدة:

| خانة | معنى عربي مختصر |
|------|-----------------|
| الوارد اليومي | دخل المشروع لليوم |
| الصادر اليومي | مصروف المشروع لليوم |
| المساهمة (في الصحيفة) | سحب من رصيد النسبة الإدارية التاريخي للمنظمة لتغطية عجز — بشروط صلاحيات |
| المصروف الإداري | تكلفة مخزون إداري (FIFO) لنفس اليوم |
| غير المغطى من المصروف الإداري | الجزء الذي لم يُغطَّ من فائض اليوم |
| مستحق إداري المشروعات / المسدد | طرف دين المصروف الإداري بين الأيام |
| النسبة الإدارية | نسبة من الوارد (أو 0 إن معفى) |
| الخصم التشغيلي | حسب نوع المشروع + جدول المعدلات الفعّالة بالتاريخ |
| إجمالي اليوم | صافي تشغيل اليوم بعد الرسوم والخصوم |
| صافي الصندوق | الرصيد التراكمي للصندوق حتى هذا اليوم |
| الدين الإداري لليوم / المتراكم | دين نسبة إدارية غير مغطاة + أثر المساهمات/Stage 3 |
| أخذ / أعطى / متبقي النسبة | حقول Stage 3 أعلاه |
| الحالة `status` | `surplus` / `deficit` / `balanced` من صافي الصندوق |
| صف الإجماليات `totals` | مجموع كل المشاريع النشطة لليوم (ليس صفحة الجدول فقط) |

اذكر أيضاً: رصيد النسبة الإدارية المتاح للمنظمة أعلى الشاشة إن ظهر.

## 3.4 محطة النقد (Cash Station)

| خانة | معنى |
|------|------|
| إجمالي الشهر / `monthly_total` | نتيجة تشغيل الشهر (من تجميع الصحائف) — **ليست** صافي الصندوق التراكمي |
| السابق | إن وُجد ترحيل شهر |
| مساهمة مضافة / مخصومة | تحويلات وتسويات الشهر |
| صافي النقد `net_cash_fund` | السابق + إجمالي الشهر + مضاف − مخصوم |
| الدين الإداري المتبقي | بعد التسويات |
| الحالة | فائض / عجز / متوازن من صافي النقد المعروض |

ملاحظة مهمة للمساهمات من نوع `administrative_debt`: تخصم من المساهم ولا تضيف نقداً للمستفيد في محطة النقد.

## 3.5 الملخص الشهري + المساهمات

| خانة البطاقة | معنى |
|--------------|------|
| `project_net_result` | **صافي الصندوق** نهاية الشهر (tip من الصحيفة) |
| `net_result_state` | فائض / عجز / محايد حسب الرقم المعروض |
| الدين الإداري | المتراكم المستحق |
| مساهمات مستلمة / مخصومة | سجلات المساهمة للشهر |

أنواع المساهمة:

| نوع | أثر |
|-----|-----|
| `fund_deficit` | يزيد صافي صندوق المستفيد وينقص صافي صندوق المساهم بنفس المبلغ |
| `administrative_debt` | يقلل دين المستفيد وينقص صافي صندوق المساهم؛ لا يزيد نقد المستفيد |

قوائم الخيارات (`available_surplus` / `remaining_need`) تعتمد صافي الصندوق وليس محطة النقد.

## 3.6 تسوية الدين الإداري

- استرداد دين من فائض شهري للمشروع.
- يؤثر على رصيد النسبة الإدارية للمنظمة وعلى محطة النقد (الدين المتبقي)، وليس كخصم مباشر من صافي النقد بنفس منطق المساهمة اليومية.

## 3.7 الصندوق الإداري

(فصل كامل في القسم 6 — هنا ملخص + إحالة.)

## 3.8 الصندوق التشغيلي

- إدخال يدوي: الصادر التشغيلي لليوم.
- الوارد التشغيلي المتوقع من إعدادات الخصم + المشاريع الثابتة.
- صافي يومي + حالة تغطية العجز التراكمي عبر أيام الشهر.

## 3.9 النسبة التشغيلية (Operational Rate)

- **ليست** وارد الصندوق اليومي من الصحيفة.
- أعمدة اليوم: وارد تشغيلي (`operational_deduction`) / صادر تشغيلي (`operational_expense` من الصندوق التشغيلي) / صافي تشغيلي.
- بطاقة إجمالية: إجمالي الصادر التشغيلي.
- أخفِ أو تجاهل `total_income` إن ظهر في JSON لكنه لا يخص هذه الشاشة للمستخدم.

## 3.10 نسب الإدارة (Administration Rates)

- تقرير قراءة: ملخص + تقويم يومي لشهر + مجاميع شهرية من الصحائف (مع استثناء المعفيين حيث ينطبق).

## 3.11 مصاريف الصندوق النقدي اليومية

- مصفوفة يوم × مشروع من `daily_expense + administrative_expense`.
- مشاريع بلا حركة شهرية تُستبعد.

## 3.12 مركز التقارير

- فترة مرنة.
- صفوف مشاريع: دخل/مصروف/إداري/تشغيلي/صافي/دين.
- رسوم بيانية للحركة وتوزيع المصروف.

## 3.13 التقارير المتقدمة

انظر القسم 4 بالكامل.

## 3.14 المخزون

- أصناف، رصيد، حد أدنى، وارد/صادر.
- FIFO للتكلفة عند الصادر الإداري (يؤثر على مصروف الصحيفة الإداري).

## 3.15 الإشعارات / التدقيق / الإعدادات

- إشعارات: تغذية نشاط عامة (ليست صندوق وارد خاص لكل مستخدم).
- تدقيق: سجل عمليات + نشاطي.
- إعدادات عامة وموظفين شهرية تؤثر على تقارير مشتقة.

# 4) التقارير المتقدمة — تركيز على المخزون

## 4.1 أنواع التقرير

| `report_type` | الاسم العربي | ماذا يعرض |
|---------------|--------------|-----------|
| `month_comparison` | مقارنة الأشهر | اتجاه إيراد/مصروف/صافي، إداري مقابل تشغيلي، معدل نمو |
| `inventory` | تقرير المخزون | ملخص أصناف + قيمة FIFO + الأكثر استهلاكاً + جدول الحالات |

المعامل `period` = عدد الأشهر المتدحرجة.

## 4.2 تقرير مقارنة الأشهر — الخانات

- إيراد / مصروف / صافي لكل شهر.
- خصم إداري مقابل خصم تشغيلي.
- نسبة نمو الصافي مقارنة بالشهر السابق (إن أمكن حسابها).

## 4.3 تقرير المخزون — اشرح كل خانة بالتفصيل

### ملخص أعلى التقرير (`summary`)

| مفتاح | عربي | شرح |
|-------|------|-----|
| `total_items` | إجمالي الأصناف | عدد الأصناف في المخزون |
| `low_stock_items` | أصناف منخفضة | عدد الأصناف بحالة `low` |
| `inventory_value` | قيمة المخزون | مجموع قيمة المتبقي بتكلفة FIFO |
| `most_consumed_item` | الأكثر استهلاكاً | أعلى كمية صادر في فترة التقرير (اسم + وحدة + كمية) أو فارغ |

### صفوف الجدول (`items[]`)

| مفتاح | عربي | شرح |
|-------|------|-----|
| `item_name` | الصنف | الاسم |
| `unit` | الوحدة | وحدة القياس |
| `total_incoming` | إجمالي الوارد | الرصيد الافتتاحي + كل الوارد التراكمي |
| `total_outgoing` | إجمالي الصادر | كل الصادر التراكمي |
| `balance` | الرصيد الحالي | الكمية المتبقية |
| `minimum_stock` | الحد الأدنى | عتبة التنبيه |
| `status` | الحالة | انظر الجدول التالي |

### معاني `status`

| قيمة | عربي مقترح | متى |
|------|------------|-----|
| `good` | جيد | الرصيد > الحد الأدنى |
| `low` | منخفض | الرصيد ≤ الحد الأدنى وما زال > 0 |
| `out_of_stock` | نافد | الرصيد ≤ 0 |

### لقطات شاشة مطلوبة

1. بطاقات الملخص الأربع.
2. جدول الأصناف مع تلوين الحالات.
3. إن وُجد رسم/بطاقة «الأكثر استهلاكاً».

### ملاحظات للمستخدم

- قيمة المخزون تعتمد FIFO وليست سعراً يدوياً للوحدة في واجهة التقرير.
- فترة التقرير تؤثر على «الأكثر استهلاكاً»؛ أرصدة الأصناف الحالية أرصدة لحظية للنظام.

# 5) شرح كل خانات الصندوق الإداري

الشاشة: **الصندوق الإداري** — شهر/سنة، صف لكل يوم + ملخص أعلى.

## تصنيف الوارد مقابل الصادر (مهم جداً)

| البند | جانب العرض الصحيح |
|-------|-------------------|
| إجمالي النسبة الإدارية (`total_administrative_percentage`) | **وارد** |
| استرداد الدين (`debt_recovery`) | **وارد** |
| إداري المشروعات (`project_administration`) | **صادر** (ليس وارداً) |
| مساهمة الصناديق (`cash_fund_contributions`) | **صادر** |
| مساهمة أفراد (`individual_contributions`) | **صادر** (إدخال يدوي) |
| إدارة تشغيلية (`operational_administration`) | **صادر** (يدوي) |
| إدارة أصول (`asset_administration`) | **صادر** (يدوي) |

## معادلة إجمالي إداري الصناديق (`total_income`) كما يحسبها النظام

```
إجمالي إداري الصناديق =
  إجمالي النسبة الإدارية
  − (إداري المشروعات غير المغطى لليوم + مساهمة الصناديق + مساهمة أفراد)
  + استرداد الدين
```

ثم:

```
إجمالي المصروفات = إدارة تشغيلية + إدارة أصول
الصافي = إجمالي إداري الصناديق − إجمالي المصروفات
```

## قاموس خانات الصندوق الإداري

| مفتاح API | اسم عربي مقترح | مصدر | يدوي؟ | شرح للمستخدم |
|-----------|----------------|------|-------|--------------|
| `total_administrative_percentage` | وارد النسبة الإدارية | مجموع `administrative_fee` من الصحيفة لليوم | لا | ما دخل للصندوق الإداري كنسب من المشاريع |
| `project_administration` | إداري المشروعات | طرف `outstanding_project_administration` (عرض الطرف) / وفي المعادلة يُطرح `uncovered_administrative_expense` | لا | مصروف إداري للمشاريع لم يُغطَّ من فائضها — يُعرض كصادر |
| `cash_fund_contributions` | مساهمة الصناديق | عمليات المساهمات | لا* | صادر مرتبط بمساهمات الصناديق (*قد يكون 0 حسب التنفيذ الحالي) |
| `individual_contributions` | مساهمة أفراد | إدخال يومي يدوي | نعم | مبلغ يُطرح من إجمالي الإداري |
| `debt_recovery` | استرداد الدين | تسويات الدين الإداري (تاريخ الإنشاء) | لا | يعيد للوارد عند تحصيل دين |
| `total_income` | إجمالي إداري الصناديق | محسوب | لا | بعد طرح الصادر ذي الصلة وإضافة الاسترداد |
| `operational_administration` | إدارة تشغيلية | يدوي من الصندوق التشغيلي/اليوم | نعم | مصروف إداري تشغيلي |
| `asset_administration` | إدارة أصول | إدخال يدوي | نعم | مصروف أصول |
| `total_expenses` | إجمالي المصروفات | مجموع البندين أعلاه | لا | |
| `net` / `administrative_net` | الصافي الإداري | محسوب | لا | |
| `notes` | ملاحظات | يدوي | نعم | نص حر لليوم |

في الملخص الشهري لنفس الشاشة: `project_administration` في الـ summary = طرف المستحق نهاية الشهر (tip)، بينما طرح المعادلة اليومية يستخدم التحويل غير المغطى لذلك اليوم — اشرح هذا الفرق بجملة لتجنب لبس المحاسب.

# 6) الملحق النهائي: قاموس كل خانات السيستم

أنشئ جدولاً كبيراً (يمكن تقسيمه حسب الشاشة) يغطي على الأقل:

### صحيفة يومية

كل مفاتيح القسم 3.3 + `available_administrative_percentage_balance` + `totals.*` + `status`.

### محطة النقد

`monthly_total`, `previous_monthly_total`, `added_contribution`, `deducted_contribution`, `net_cash_fund`, `remaining_administrative_debt`, `status`, التسويات، الترحيل.

### ملخص شهري

`project_net_result`, `net_result_state`, `administrative_debt`, `total_received_contributions`, `total_deducted_contributions`, `contribution_type`, `available_surplus`, `remaining_need`.

### صندوق إداري / تشغيلي / نسبة تشغيلية / نسب إدارة / مصاريف نقدية

كل المفاتيح المذكورة في الأقسام السابقة.

### تقارير متقدمة

مفاتيح `month_comparison` و `inventory` بالكامل.

### مخزون تشغيلي

اسم الصنف، وحدة، وارد، صادر، رصيد، حد أدنى، نوع الحركة، مشروع مستفيد، تكلفة FIFO إن ظهرت.

### مشاريع

الاسم، التصنيف، الحالة، إعفاء إداري، نسبة إدارية، نوع خصم تشغيلي، معدلات الخصم الفعالة بتاريخ.

لكل صف في القاموس الأعمدة: **الشاشة | اسم الخانة عربي | المفتاح التقني إن وُجد | معنى بجملة | محسوب/يدوي**.

# 7) تعليمات الإخراج لـ Claude

1. اكتب المحتوى **بالعربية الفصحى المبسطة**.
2. أنتج أولاً مسودة Markdown كاملة بنفس ترتيب الهيكل.
3. ثم حوّلها إلى PDF (أو HTML جاهز للطباعة إن تعذر PDF مباشرة) مع:
   - عنوان رئيسي لكل فصل
   - جداول منسقة
   - أرقام الأشكال
   - هوامش مناسبة للطباعة A4
4. لا تترك مصطلحات إنجليزية دون ترجمة إلا مفاتيح API بين قوسين عند الحاجة للمطورين.
5. في نهاية المستند: صفحة «أخطاء شائعة» من 8–10 نقاط (مثال: خلط إجمالي الشهر مع صافي الصندوق؛ اعتبار إداري المشروعات وارداً؛ إعادة حساب Stage 3 يدوياً في الواجهة…).
6. إذا طلب المستخدم لاحقاً إدراج صور، اطلب منه مجلد لقطات بأسماء ملفات مطابقة لعناوين الأقسام.

## جملة الافتتاح التي تقولها Claude للمستخدم قبل البدء

«سأجهّز دليل PDF عربي لنظام رشيد يغطي سد العجز اليومي من النسبة الإدارية، شرح كل الشاشات، التقارير المتقدمة وخاصة المخزون، خانات الصندوق الإداري، ثم قاموساً لكل خانات النظام. سأبدأ بمسودة Markdown ثم ملف قابل للطباعة.»
